## 实现过程中的关键修订（相对方案文本的落地事实）

1. **Calcite 1.42 API 形态**：命名函数（含生成列 IF）`SqlKind=OTHER_FUNCTION`（非 OTHER）；INSERT VALUES 解析为单个 `SqlBasicCall(kind=VALUES)`，operands 即各行。
2. **整型统一 BIGINT**：存储侧整型为 Long，类型映射全部映射 SqlTypeName.BIGINT；映射 TINYINT/INTEGER 会在 enumerable 运行期触发 Long→Integer CCE（多列投影/JOIN 时）。
3. **时间戳墙钟对齐**：scan() 将 Timestamp 转为「本地墙钟按 UTC 计」的 long（avatica accessor/参数层的转换约定），避免多列投影路径的 ±时区漂移；Nanosecond 精度不受影响（毫秒级）。
4. **字符串字面量 UTF-8 introducer**：Calcite 类型工厂默认字面量字符集 ISO-8859-1，与列类型 UTF-8 相异时生成 ISO-8859-1 CAST 使中文字面量运行期编码失败；`SqlCharsetRewriter` 给单引号字面量加 `_UTF8`（幂等，跳过注释/反引号/N''）。
5. **裸 `?` 的类型锚定**：UPDATE/INSERT 表达式改写为 internal SELECT 时，SET 裸动态参数以 `CAST(? AS <列类型>)` 锚定（无上下文 ? 过不了校验）；LIMIT 参数按 ParameterMetaData 做 Long↔Integer 适配（MP 分页 offset 为 Long）。
6. **二次 shade 常量池溢出**：junit5 工件 shade mybatis uber jar 时，对已重定位类二次处理推动近限常量池溢出（SqlFunctions 65536）；junit5 shade filters 排除 `cn/vv/test/shaded/**`（原始依赖在本模块内重新 shade 生成同名内容）。另需重申全局 `META-INF/versions/**` 排除（jackson multi-release 高版本 class）。
7. **junit5 模块测试线**：`junit-jupiter` 聚合件 5.4.0 起才存在；模块以 `junit-jupiter-api` 5.3.2 编译基线（provided）+ `junit-jupiter-engine`/`junit-platform-launcher` 5.3.2/1.3.2 测试运行（避免与父 pom 5.10.2 聚合件混版触发 PreconditionViolation）。
8. **模块内测试的类新鲜度**：junit5 模块直接前置依赖 calcite/jdbc 模块 jar，避免测试类加载被 mybatis 工件内联的旧类遮蔽（消费方依赖形态不受影响）。
9. **animal-sniffer 未加装**：唯一构建/测试线即 JDK 8（javac 1.8 bootclasspath 拦截 JDK 9+ API）+ T12 字节码断言；签名插件与构建线语义重复，不加装。
10. **MyBatis-Plus 工厂装配**：`MybatisSqlSessionFactoryBuilder` 会以默认 GlobalConfig 覆盖定制（MetaObjectHandler 失效），装配助手统一经 `DefaultSqlSessionFactory`（MybatisConfiguration + 自建 GlobalConfig）；MP 3.4.3.4 的 mapper 注入路径需要 spring-core（MP 侧 optional，消费方自带）。
11. **MyBatis 3.5.x 更新计数**：`PreparedStatementHandler` 走 `execute()+getUpdateCount()`，JDBC 层 execute() 必须维护 updateCount 状态位。
12. **查询侧字符串比较为二进制**（已知差异登记）：清单内 _ci collation 的唯一键/等值归一已实现（D-16 存储侧）；SELECT 等值与 GROUP BY 走 Calcite 默认二进制比较，大小写变体在查询侧不合并——列入已知差异表；差分语料未覆盖查询侧 _ci 等值场景，后续语料补充时跟踪。
13. **缺列 NOT NULL 两态错误码**（差分对齐 MySQL 实测）：INSERT 缺列且 NOT NULL 无默认 → 1364/HY000（ER_NO_DEFAULT_FOR_FIELD）；显式插 NULL → 1048/23000。检查点在 ModificationExecutor.fillDefaults（拥有 provided 语义），MemoryTable.checkNotNull 保留为显式 NULL 形态。
14. **DATETIME/TIMESTAMP fsp 语义**（差分对齐 MySQL 实测）：DDL 括号数字是 fsp（小数秒位）非长度——解析层记入 scale；无精度声明（scale<=0）时入库按秒**四舍五入**（03:04:05.678 → 03:04:06），DATETIME(n) 按 D-08 保精度；CURRENT_TIMESTAMP 默认值同经 coerce 舍入。
15. **Boot 装配链依赖形态**：autoconfigure 依赖 mysql-mock-junit5（shaded uber，消费方依赖树零新增）；spring-boot-autoconfigure 2.1.3 / spring-test 5.1.3 / slf4j 均 provided。模式 A 的 BDRPP 保留原定义 primary/lazy 标志，其余属性不迁移（目标即 DataSource，接管后语义完全替换）。
16. **reactor 形态的类路径污染**（构建基建）：全仓/`-am` 构建时 Maven 向 compat 注入内部模块 target 产物及 SS/groovy 传递链，exclusions 不生效（workspace resolution 已知行为）——原始 groovy 触发 Spring 的 groovy 探测且初始化失败。compat 以 surefire `classpathDependencyExcludes` 排除 org.apache.groovy:groovy（SS DDL 门禁仅用 ANTLR，不受影响）；消费方安装形态（单模块跑）本就干净。
17. **shade 半成品自锁**：shade 失败会把重定位类残留在模块 primary jar，后续非 clean 重跑在读取该 jar 时复现同错（SqlFunctions 65536 假阳性）——shade 工件变更后必须 clean。
